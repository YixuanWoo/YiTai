## 第一批：零风险清理（不碰数据、不改行为）

- [ ] **T-1 拔掉"原文"措辞（约 76 处）**
  代码注释、README、界面文案里的"原文"统一成"资料 / 文件 / 译文"。
  这是旧模型最强的传染源：新读者先看到"原文"，就会按"一份原文配一份译文"去写。
  *验收*：全文搜索 `原文` 只剩"原文栏"这种明确的对外说法（或 0 处）；界面文案无"原文"。

- [ ] **T-2 删 `TextStats.ChineseNumber`**
  Core 内零引用（只有外部一次性迁移脚本用过）。1..99 的中文数字转换不属于翻译工具的核心职责。
  *验收*：删除后编译通过；`git grep ChineseNumber` 为 0。

- [ ] **T-3 去掉重复的 `LastSourceId`**
  `AppSettings.LastSourceId` 与 `ProjectMeta.LastSourceId` 语义重叠，界面只认后者。
  *验收*：旧 `settings.json` 缺该字段可正常启动；`AppSettings` 只剩窗口尺寸 / 自动保存间隔 / 上次项目根。

- [ ] **T-4 `ProjectLayout.EnsureCreated` 不再强建 `sources\`**
  归档目录是可选的，建它只是在暗示"必须先有原文"。
  *验收*：新建空项目后目录只有 `project.json / translations / backups / .yitai`。

- [ ] **T-5 `RefKind` 折叠**
  四值枚举里三个已是死语义，默认值还指向死值。
  *验收*：只剩实际使用的种类；默认值与"未知/纯文本"一致；旧 pane 布局 JSON 仍能读。

- [ ] **T-6 补应用图标**
  `csproj` 目前没有 `ApplicationIcon`，exe、任务栏、资源管理器里都是空白默认图标。
  *验收*：`YiTai.exe` 有图标；窗口标题栏左上角有图标；多尺寸（16/32/48/256）。

- [ ] **T-7 补 `==高亮==` 的解析单测**
  目前只手工截图验证过。要覆盖：正常配对、未闭合原样保留、跨行不匹配、与 `**粗**` 嵌套时的当前行为（不解析内层）。

- [ ] **T-8 README 补"已知边界"**

## 第二批：动数据模型（先备份 .yitai 与 project.json）

- [ ] **T-9 重写旧链路 + 17 项废测试**
  `ProjectStore` 里"源文件 → 译文"的整条旧链路（约 204 行）连同对应测试一起删改。
  **必须同时动**，否则编译不过。
  *验收*：`project.json` 只剩"译文清单 + 栏位"；34 项测试重写为测真实链路；全过。

- [ ] **T-10 `SourceEntry.TranslationPath` 降级或删除**
  这个字段本身就在说"每份源文件有一份译文"。若仍需兼容旧项目，改成只读兼容（读到就忽略）。
  *验收*：新写出的 `project.json` 不再含该字段；旧项目打开不报错。

- [ ] **T-11 进度键从"纯文件名"改绝对路径**
  同名文件在两个目录下会互相覆盖进度。
  *耗时点在迁移*：要把旧的按文件名的键映射到新键，跑一次并保留旧文件。
  *验收*：同一个文件名放在两个目录，进度互不干扰；迁移后再打开旧项目绿线位置不变。

- [ ] **T-12 PDF 两条实现二选一**
  现状：原件由 WebView2 画，文字抽取那条路径已不可达，却仍带着 `PdfText.cs`（220 行）与 `PdfPig` 依赖。
  方案 A：删文字抽取，只留原件 + 明确"不做 OCR"。
  方案 B：做成栏头可见开关（原件 / 文字），文字层供搜索与复制。
  *需拍板*：选 A 还是 B（B 会多一个依赖与一类失败提示）。
